# Слепая человеческая разметка родительского внимания

Цель — отметить то, что стоит показать родителю, не превращая игровые слова, мягкие насмешки и неоднозначные фразы в тревогу. Этот пакет содержит полные субтитры, но не оценки и карточки модели. Он не позволяет судить о неописанных изображениях и звуке.

## Порядок работы

1. Скопируйте `annotations.template.json` в `annotations.json`. Шаблон можно перегенерировать; заполненные ответы генератор не меняет.
2. Прочитайте весь транскрипт, включая развязку. Для каждой существенной сцены заполните одну запись в `labels`. Несколько категорий одного эпизода не требуют отдельных записей.
3. Отметьте также неоднозначные/безобидные контрольные эпизоды, которые алгоритм мог бы ошибочно показать. Не нужно размечать каждую безобидную реплику.
4. Укажите прямые доказательства через индексы сегментов. Несмежные доказательства записывайте несколькими диапазонами; не растягивайте один диапазон на весь сюжет. Описание должно следовать из этих доказательств, а не из предположений о картинке.
5. Запишите причину решения. Для спорного эпизода оставьте `complete=false` и передайте его второму человеку. Не заставляйте неопределённость превращаться в положительную/отрицательную метку.
6. После полного разбора укажите `reviewerId`, `reviewedAt` (ISO UTC), `blindedToModelOutput=true`, `reviewedEntireTranscript=true`, `complete=true`. Эти поля — свидетельство человека; агент их не заполняет за разметчика. Пустой `labels` допустим только после полного чтения: это отрицательный пример, а не отсутствие разметки.

## Уровни

- `hidden` / `hidden`: отдельная карточка не нужна — утилитарное действие, отрицание, случайное слово, неподтверждённая интерпретация.
- `details` / `low` (или `moderate`): лёгкий, обычный игровой либо спорный материал, который не должен привлекать основное внимание.
- `main` / `moderate`: конкретная сцена заслуживает внимания; например, повторяемое нежелательное действие с подтверждённым distress. Одиночного «хватит» недостаточно.
- `main` / `high`: исключительный значимый эпизод с конкретным усилителем, а не просто высокая уверенность модели или слово «оружие».

Категории: `profanity_and_rude_language`, `insults`, `toilet_humor`, `violence`, `scary_and_disturbing`, `sexual_content`, `gambling`, `substances`, `self_harm`.

Пример формы (условный, не готовая разметка ролика):

```json
{
  "id": "scene-1",
  "categories": ["violence"],
  "evidence": [{"firstSegment": 20, "lastSegment": 22}],
  "priority": "details",
  "level": "low",
  "rationale": "Указать наблюдаемое действие и почему оно заслуживает только подробностей."
}
```

## Независимость и метрики

Все нынешние локальные ролики уже участвовали в настройке: `tuning`, `previouslyUsedForTuning=true`. Не переименовывайте их в holdout. Для независимого теста нужны заранее выбранные новые каналы и ролики, не выбранные по результатам модели. Желательны разные форматы, возрастные аудитории и отрицательные примеры; выборку и критерии следует зафиксировать до запуска сравнения coverage on/off. После настройки по результатам holdout он становится tuning для следующей итерации.

Изменение текста или таймкодов делает разметку неприменимой: валидатор проверяет SHA-256. В метриках учитываются только полностью разобранные человеком видео; незаполненная разметка не даёт «100% точности».

Один эпизод может подтвердить не более одной карточки. Главная карточка не получает зачёт за эпизод, который человек назначил в details. Избыточный high учитывается отдельно. Совпадение категории и времени — лишь кандидат на корректную карточку: достоверность её текста, ролей и смягчающего контекста нужно отдельно проверить человеку после слепой разметки.

Команды:

```bash
npm run eval:prepare-human-review
QUALITY_HUMAN_GOLD_PATH=benchmark-results/human-review/annotations.json npm run eval:parental-quality
```

Первая команда локальная и бесплатная. Вторая вызывает модель и требует сохранённых scans, подходящих выбранной разметке. Установите `QUALITY_SCAN_DIRS`/`QUALITY_VIDEO_IDS` для нужной выборки. Сначала выполните одинаковую выборку с `QUALITY_ENABLE_COVERAGE=0`, затем с `QUALITY_ENABLE_COVERAGE=1`; повторите с зафиксированными порядками. Результаты tuning и holdout не смешивайте.
